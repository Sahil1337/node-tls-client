---
title: ClientIdentifier
description: Every built-in browser and app profile.
---

```js
import { Session, ClientIdentifier } from "node-tls-client";

const session = new Session({ clientIdentifier: ClientIdentifier.firefox_148 });
```

`ClientIdentifier` is a string enum of the profiles built into the native library. Each one sets the whole TLS and HTTP/2 fingerprint of that browser or app version. It does **not** set headers such as `User-Agent`; send those yourself. See [Browser profiles](/guides/browser-profiles).

- **Default:** `chrome_150`, used when a session has neither `clientIdentifier` nor `ja3string`.
- **`_psk` / `_PSK` variants** add the TLS `pre_shared_key` extension, so repeat connections resume the TLS session the way a returning browser does.
- **HTTP/3:** only `chrome_144`, `chrome_144_psk`, `firefox_147`, `firefox_147_psk` and `firefox_148` carry real HTTP/3 settings (native 1.16.0). See [HTTP/3](/guides/http3).
- **Unknown names fall back to `chrome_150`** without an error. `chrome_154`, `chrome_154_psk` and `safari_27_2` need native 1.18.1 or newer: `initTLS()` downloads that, but a previously cached library it falls back to (with a warning) may be older.

In code, use the enum key (`ClientIdentifier.chrome_131_psk`). In plain JavaScript you can also pass the value string (`"chrome_131_PSK"`); for some profiles the two differ in case.
